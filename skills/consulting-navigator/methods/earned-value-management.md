# Earned Value Management
## Purpose
Measure project performance by integrating planned value, earned value, and actual cost into objective schedule and cost indices and forecasts. It replaces subjective progress colors with a time-phased view of work accomplished for the money spent.
## Use
- Objectively integrating scope, schedule, and cost performance against a performance measurement baseline
- Forecasting estimate-at-complete and variance trends mid-execution
- Comparing multiple projects with a common earned-value language
## Avoid
- There is no baselined work package structure or planned value curve—build the plan with critical-path-method and pmbok-framework first
- The engagement is pure agile discovery with volatile scope and no PV baseline—use scrum-framework metrics (velocity, burndown) instead
- You only need strategic outcome KPIs, not project cost/schedule integration—use balanced-scorecard or okrs-style outcome tracking via performance-management-system
## Inputs
**Must-have:** Performance measurement baseline with planned value over time; Work packages or control accounts with budgets; Actual cost data by period; Earned value rules (e.g., 0/100, percent complete, milestones) and progress evidence.

**Nice-to-have:** resource forecasts, change log, schedule network, and risk-register contingency drawdown.

**When data is thin:** use only objectively verifiable milestones and flag control accounts without cost actuals as incomplete.
## Procedure
1. Freeze the performance measurement baseline by time-phasing authorized work-package budgets into planned value (PV). Assign control-account managers and define change-control rules.
2. Choose earning rules that match each package: 0/100, weighted milestones, apportioned effort, or physical percent complete. Define objective evidence required to claim earned value (EV).
3. At each status date, collect actual cost (AC) from finance and validate completed work against the earning rule. Reconcile late costs and approved scope changes before calculating variance.
4. Calculate schedule variance EV − PV, cost variance EV − AC, schedule performance index EV/PV, and cost performance index EV/AC. Investigate material deviations at control-account level rather than averaging them away.
5. Forecast estimate at completion using the chosen performance assumption, compare it with budget at completion, and assign corrective actions, change requests, or management escalation.
## Output Contract
A measurement framework and reporting pack with the baseline, status date, PV/EV/AC by control account, variance and index trends, estimate-at-complete method, forecast range, explanations, and corrective actions. The pack must state whether variance reflects unauthorized scope, timing, cost efficiency, or flawed measurement and name an owner for each material exception.
## Evidence
Approved budgets, accepted deliverables, invoices, and time charges are observed. Estimated accruals and forecast productivity are inferred. The EAC formula, performance trend persistence, and allocation of indirect costs are assumptions that must be disclosed. Missing actuals, unaccepted deliverables, and unapproved scope changes are unknowns; they cannot be converted into earned value to make an index look healthier.
## Checks
- PV, EV, and AC share the same work-breakdown structure and status date.
- Every EV claim has acceptance evidence consistent with its earning rule.
- Cost actuals are reconciled to the ledger and accrual treatment is clear.
- CPI and SPI are accompanied by variance drivers and an EAC calculation.
- Baseline changes are authorized and separately visible from performance variance.
## Failure Modes
- Awarding 90 percent earned value because a task “feels almost done” without a milestone acceptance.
- Comparing this month’s actual costs with cumulative planned value and reporting a misleading CPI.
- Resetting the baseline after every unfavorable forecast so overruns disappear from history.
