# Digital Maturity Assessment
## Purpose
Score current digital capabilities against a structured maturity model to expose gaps and investment priorities. It gives leaders a calibrated baseline across dimensions before they design a transformation program.
## Use
- Baselining digital capability across strategy, experience, operations, data, and tech
- Prioritizing transformation investments against a transparent maturity model
- Creating a shared fact base before digital or AI transformation design
## Avoid
- You already know gaps and need the transformation program design—use digital-transformation-framework
- The question is only AI portfolio design—use ai-strategy-and-roadmap after a lighter tech baseline
- You need continuous ops performance metrics, not capability maturity—use balanced-scorecard
## Inputs
**Must-have:** Defined maturity dimensions and scoring rubric; Evidence from systems, processes, talent, and customer experience; Stakeholder interviews across business and technology; Optional external benchmarks for peer comparison.

**Nice-to-have:** architecture diagrams, journey performance measures, data-quality metrics, and past transformation results.

**When data is thin:** score only dimensions supported by evidence and show an unscored status rather than fabricating a level.
## Procedure
1. Set the enterprise boundary, assessment period, dimensions, and maturity-level definitions. Calibrate scorers using two sample capabilities so a level means the same thing across domains.
2. Build an evidence register for each dimension from interviews, artifacts, metrics, and demonstrations. Record the capability being scored rather than accepting broad claims such as “we are data driven.”
3. Score each capability against observable rubric anchors, with two independent reviewers resolving material differences. Preserve both the level and the rationale.
4. Aggregate results into a heatmap, then identify cross-dimensional constraints: for example, a customer-experience ambition blocked by data ownership and platform release cadence.
5. Prioritize gaps by value at stake, feasibility, dependency, and confidence in the score. Produce a short list of baseline facts that the next transformation design must address.
## Output Contract
An assessment with maturity definitions, dimension and capability scores, evidence references, scorer confidence, benchmark context where comparable, gap heatmap, and prioritized constraints. It must make clear which scores are measured, jointly judged, or withheld, and it must not masquerade as the delivery roadmap that follows.
## Evidence
System telemetry, process records, customer metrics, and observed demonstrations are evidence. Interview consensus is inferred unless corroborated. Rubric interpretation and benchmark comparability are assumptions that need a calibration note. Missing artifacts, untested claims, and dimensions outside the boundary are unknown; represent them separately from low maturity so executives do not fund the wrong remedy.
## Checks
- Each score cites a specific rubric anchor and evidence item.
- Different dimensions use the same level definitions, not different standards by function.
- Interviewees include business, technology, data, and frontline perspectives.
- A benchmark is compared only where scope and scale are genuinely comparable.
- Priorities account for dependencies rather than sorting solely by the lowest score.
## Failure Modes
- Averaging a strong mobile app with weak data governance and hiding the bottleneck.
- Letting executives self-score without artifact review, producing aspiration rather than baseline.
- Ranking every low score equally when some capabilities have no link to a value pool.
