# Value-Based Pricing
## Purpose
Set list prices, packages, and metrics from quantified customer value versus alternatives rather than cost-plus or pure competitive matching. It turns a buyer's economic or perceived upside into defensible price fences rather than treating production cost as the value ceiling.
## Use
- Price should reflect differentiated economic or perceived value versus next-best alternatives
- You are redesigning list price, packaging, or metrics after a value proposition shift
- Cost-plus or pure competitor matching is destroying margin or brand
## Avoid
- You first need to quantify behavioral price response—use price-elasticity-analysis
- Leakage between list and pocket is the main problem—use pricing-waterfall-analysis
- Willingness-to-pay by feature configuration is unknown—use conjoint-analysis or price-sensitivity-meter first
## Inputs
**Must-have:**
- Customer value drivers and quantified benefits versus alternatives
- Competitive reference prices and next-best alternatives
- Cost floors and strategic positioning constraints
- Segment differences in value perception and willingness to pay

**Nice-to-have:** realized segment discounts, win-loss interviews, and a usage model for package outcomes.

**When data is thin:** separate verified benefits from buyer claims, use ranges, and restrict offers to reversible pilots.
## Procedure
1. **Choose a purchase occasion and reference alternative.** Define the segment, use case, buying unit, and alternative: retain the incumbent, hire labor, or accept the problem. Output: value-comparison frame.
2. **Build the value ledger.** Quantify each material benefit in the customer's units: avoided downtime, revenue gained, labor removed, risk reduced, or experience improved. Show the calculation, adoption conditions, and who receives the benefit. Output: segment value ledger.
3. **Set the value share and price corridor.** Establish a lower bound above the cost floor, a reference-relative ceiling, and the provider's share of incremental value. Use the corridor as a negotiation guardrail. Output: price corridor by segment.
4. **Design packages and fences.** Bundle features, service levels, metrics, or commitment terms so high-value users can select a higher tier without giving low-value buyers an arbitrary penalty. Test that each fence is observable, enforceable, and linked to value received. Output: package architecture and qualification rules.
5. **Validate with buyers and sales.** Run price conversations, proposals, or controlled offers; record objections, realized value evidence, and discount requests. Adjust the corridor only when the evidence changes the value logic. Output: launch recommendation with validation plan.
## Output Contract
A pricing decision pack with the purchase occasion, reference alternative, value ledger, calculations, price corridors, package definitions, fences, cost-floor checks, and exception rules. It tags verified versus modeled benefits and names the next test. It enables a list-price and packaging decision, not an elasticity forecast or invoice-leakage diagnosis.
## Evidence
Classify benefit evidence as observed, customer-asserted, modeled, or unknown. Keep the buyer calculation separate from seller margin. State realization rate, time horizon, switching cost, and reference alternative because each moves the corridor. Do not add benefits merely because a feature exists. Use a conservative range for unmeasured outcomes.
## Checks
- Every value claim has a unit, quantity, beneficiary, and comparison point.
- The proposed price remains above the relevant cost floor and below a defensible share of value.
- Packages differ through a real value driver rather than arbitrary feature piles.
- Sales can explain the calculation without promising undeliverable outcomes.
- Exception rules prevent one discount from redefining list price.
## Failure Modes
- Counting the same labor saving in both productivity and avoided cost.
- Using the vendor's feature list as proof that buyers receive value.
- Setting one global price when regulated, enterprise, and small-business segments realize different benefits.
- Building tiers that customers can easily game because the fence is not observable.
- Letting a loud procurement objection erase a well-supported customer outcome without testing it.
