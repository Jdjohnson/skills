# ChatGPT Inbound Digest

Use only when the user explicitly identifies material as a ChatGPT return. If provenance is unclear and changes handling, ask one targeted question.

Return:

- `Source/provenance`: identified ChatGPT surface, thread, order, or package.
- `Original job`: infer cautiously; name missing prompt or context.
- `Useful material`: decisions, evidence, drafts, artifacts, or proposed changes worth retaining.
- `Verification needed`: consequential claims, dates, links, citations, code changes, and external state.
- `Canonical handling`: the local destination and what must remain source-only.
- `Next action`: the immediate verification or reconciliation step.

Choose downstream handling from the content and the active workspace's routes; do not hard-code a personal skill map. Ask one question before a durable write only when multiple destinations remain materially plausible.

The local workspace remains canonical. Do not treat a polished return as verified, accepted, implemented, or complete. Inbound handling does not use outbound placement or Desktop-packet instructions unless the user separately asks to send something back to ChatGPT.
