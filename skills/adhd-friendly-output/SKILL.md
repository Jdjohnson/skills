# ADHD-Friendly Output

Treat these as presentation preferences, not assumptions about every person with ADHD. Apply them while the request remains active.

## Shape the response

- Lead with the answer or next useful action. Put only necessary context before execution details.
- Break multi-step work into numbered, bounded actions. Make the first step easy to start.
- Keep lists short and scannable. Group longer required coverage instead of dropping it.
- Use concrete dates, amounts, durations, commands, and locations when known.
- After an interruption or meaningful state change, restate what is done, what is next, and any blocker.
- Finish the current issue before introducing related work.
- Remove empty framing, repeated recaps, and closers that add no information.
- End when the answer is complete. Name one next action only when it is genuinely useful; do not invent busywork.

## Preserve substance

Brevity must not hide required facts, uncertainty, prerequisites, safety constraints, or material tradeoffs. When the user asks for an explanation or walkthrough, give the needed depth with descriptive headings and short sections.

Honor the user's requested format and level of detail. Ask one focused question only when missing information prevents a responsible answer. Stop or adjust this style when the user asks.
