# Reference sourcing

Real photographs are the evidence layer. Quality and truthfulness control selection; legal convenience does not rescue a misleading image.

## Selection order

1. Use the user's supplied photograph when it is the object of analysis.
2. Use an approved catalog photograph.
3. Search approved real-photography sources for a better subject-appropriate match.
4. Generate one clearly labeled combination study only when no adequate real photograph demonstrates the requested combination.

Research anchors and user-facing display assets are different records. A culturally or historically canonical photograph may inform terminology without being eligible to copy, bundle, or display.

## Source classes

### Open discovery and archives

- **Openverse:** discovery layer for openly licensed media. Verify the original source page and license; Openverse metadata alone is not final proof. <https://api.openverse.org/>
- **Wikimedia Commons:** verify each file page, creator, license, attribution, and non-copyright restrictions. Commons itself warns that file metadata is not warranted. <https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en>
- **Library of Congress:** strong historical and documentary source. Read the item's Rights Advisory; the Library usually cannot grant permission and makes the user responsible for assessment. <https://www.loc.gov/research-centers/prints-and-photographs/researcher-resources/copyright-and-rights-and-restrictions-information/>
- **Smithsonian Open Access:** prefer items explicitly marked CC0; retain item metadata and source URL. <https://www.si.edu/openaccess>
- **The Met Open Access:** use only items explicitly marked public domain/Open Access for bundled assets. <https://www.metmuseum.org/about-the-met/policies-and-documents/open-access>

### Contemporary real-photography sources

- **Unsplash:** current submission rules reject generative-AI photographs but also accept 3D renders, so verify that an asset is a real photograph. API display requires hotlinked API URLs and visible photographer/Unsplash attribution. Do not download API results into the catalog or omit required links. <https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines> and <https://help.unsplash.com/en/articles/2534415-unsplash-submission-guidelines>
- **Pexels:** current upload rules reject generative-AI content. Record the exact photo page, creator, direct image URL, and current Pexels License; manually confirm that the item is a real photograph. Keep Pexels references remote in public distributions instead of bundling or redistributing the files. Treat third-party rights in people, brands, art, and property separately. <https://www.pexels.com/license/> and <https://help.pexels.com/hc/en-us/articles/27453505326873-Can-I-upload-generative-AI-photos-and-videos-to-Pexels>
- **Flickr:** use license-filtered results and comply with the photographer's terms. API access does not override image ownership or restrictions. Do not retain remote images after privacy/license changes. Use EXIF only when the public record actually returns it. <https://www.flickr.com/help/terms/api> and <https://www.flickr.com/services/api/flickr.photos.getExif.html>

### Research only

- **ShotDeck:** useful for vocabulary around cameras, lenses, framing, lighting, color, and composition. Do not automate, scrape, copy, bundle, or redistribute its images. Use it only through manual, authorized research. <https://shotdeck.com/welcome/terms>
- Copyrighted editorial, fashion, documentary, or photographer portfolio pages may ground research. Do not make them candidates unless their actual display terms permit it.

## Eligibility gates

A user-facing candidate must:

- be a verified real photograph, unless explicitly labeled `generated combination study`;
- have an exact source page;
- have a lawful display basis recorded;
- render reliably in the active host;
- be detailed enough for the claimed visual inspection;
- pass full-size and conversation-scale visual review;
- teach the mapped term or look strongly;
- avoid unresolved privacy, publicity, trademark, property, or cultural problems material to this personal reference use.

Reject unclear, broken, thumbnail-only, all-rights-reserved copied, editorial-only bundled, noncommercial-only bundled, no-derivatives modified, or generative content presented as photography.

## User-facing treatment

Keep the candidate clean. Show credit only when the display terms require it. Do not show license codes, checksums, review states, or legal notes unless the user asks or a limitation affects the choice.

## Review record

For local assets, preserve exact source, creator, license, access date, modification, checksum, and review. For approved remote display, preserve the source-authorized URL and required credit/link behavior. For generated studies, preserve the exact prompt, tool/model label, date, and output path, and label the image synthetic in every user-facing use.

Recheck source availability and display terms before final installation. Source terms can change.
