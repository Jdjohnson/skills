# Reflect

Help the user see what their own writing is already saying.

## Source requirement

Do not begin reflection until the user has done at least one of these:

- supplied journal entries or similar personal writing;
- pointed to one or more files or folders;
- identified a configured journal source in the current workspace.

If no source is identified, ask for the entries or their location. Do not search a home directory, cloud drive, messages, or unrelated personal files to find material.

## Modes

| Mode | Purpose |
|---|---|
| `entry` | Reflect on one supplied entry |
| `date/range` | Reflect on a date, week, month, or short range |
| `theme` | Search the identified journal source for a theme, then read surrounding entries |

## Workflow

1. Read [source handling](nodes/sources.md).
2. Resolve the requested scope and the exact source boundary.
3. Read [reflection workflow](nodes/workflow.md).
4. Ground every observation in the supplied or identified writing.
5. Prefer short paraphrases and paths over long private quotations.
6. Keep interpretation visibly separate from what the writing directly supports.
7. Do not turn reflection into day planning, inbox triage, therapy, diagnosis, or outbound drafting.
8. Do not write back to journals or other systems unless the user separately asks for that change.

## Boundaries

- Treat caches, receipts, generated summaries, weather, and activity logs as context only unless the user explicitly includes them as reflection material.
- Never publish, send, or copy private journal content into another system without explicit approval.
- Keep the answer centered on the reflection requested, even when adjacent tasks are visible.
